# LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory

> 来源文件：`longmemeval.pdf` · 整理自 DeepSeek 对话阅读笔记 · [返回综述](../survey.md)

好的，我已仔细阅读并分析了您上传的论文《LongMemEval: Benchmarking Chat Assistants on Long-Term Interactive Memory》。这是一篇来自UCLA和Tencent AI Lab的研究工作，专注于构建聊天助手长期交互记忆能力的综合评测基准。

以下是对该论文核心内容的系统分析与总结：

## 1. 核心问题与动机

论文指出现有长期记忆评测基准存在两大不足：

交互历史不真实：许多基准仅关注人-人对话，忽略了任务导向的用户-AI交互（这是聊天助手的主要使用场景）；历史长度通常不可配置，且仅数千token，难度有限。

记忆能力覆盖不全：现有基准（如MemoryBank、PerLTQA）未能充分评估跨多个会话的综合推理、助手侧信息的回忆、以及基于更新后用户信息的推理。即使是LoCoMo也未能评估助手提供的信息的回忆或基于更新信息的推理。

核心动机是构建一个历史长度可自由扩展、全面覆盖核心记忆能力的评测基准，以系统性地衡量聊天助手在长期交互中的记忆表现。

## 2. 提出的方法：LongMemEval基准

五类核心记忆能力能力 描述信息提取（IE） 从大量交互历史中回忆用户或助手提到的具体信息多会话推理（MR） 跨多个历史会话综合信息，回答需要聚合和比较的复杂问题知识更新（KU） 识别用户个人信息的变化，动态更新对用户的认知理解用户信息的时间维度，包括显式时间提及和时间戳元数时间推理（TR）据弃权（ABS） 识别问题所询问的信息未被提及，正确回答"我不知道"

七种问题类型单会话-用户、单会话-助手、单会话-偏好、多会话、知识更新、时间推理、弃权。

数据构建管线

## 1. 问题策展：基于164个用户属性本体，LLM生成用户背景段落，人工筛选和改写种子问答对，

并分解为证据陈述。

## 2. 证据会话构建：将每个证据陈述嵌入任务导向的对话会话中，用户LLM被指示间接传达信息

（如通过询问车险来透露买车）。

## 3. 历史编译：仿照"大海捞针"测试，将证据会话随机插入大量不相关会话中，分配合理时间

戳。支持任意长度：LongMemEval_S（~115k tokens）和LongMemEval_M（500会话，

~1.5M tokens）。

评估指标问答：LLM-as-judge（GPT-4o），与人类专家一致率>97%。

记忆召回：Recall@k和NDCG@k（基于人工标注的答案位置）。

## 3. 实验与主要结果

商业系统评估（Figure 3a） ChatGPT（GPT-4o）准确率0.5773，Coze（GPT-4o）仅0.3299。

相比离线阅读（0.9184），ChatGPT和Coze分别下降37% 和64%。

ChatGPT倾向于在压缩历史时覆盖关键信息，Coze则经常无法记录间接提供的用户信息。

长上下文LLM评估（Figure 3b） GPT-4o在LongMemEval_S上仅0.6063，相比Oracle（仅证据会话）下降30.3%。

Llama 3.1 70B下降55.1%，8B下降36.1%。

即使应用Chain-of-Note，下降幅度仍在30%-66%。

4. 关键分析与洞察

  长上下文≠好记忆：即使提供完整历史，长上下文LLM仍表现不佳，说明模型无法有效利用长
  上下文中的信息。

  轮次优于会话：将对话分解为轮次级粒度进行存储和检索，比以整个会话为单位效果更好。

  事实增强键扩展最有效：将提取的用户事实拼接到原始值作为键，既保留了压缩信息的聚焦

  性，又保留了原始值的完整性。

  时间感知查询扩展依赖强LLM：GPT-4o能准确推断时间范围，而Llama                3.1 8B经常在无时间

  引用的问题上错误提取时间范围，导致召回下降。
  阅读策略至关重要：即使完美检索，次优阅读策略仍可导致10个绝对点的性能下降。

  CoN+JSON格式在所有模型上一致最优。

关键区别：LongMemEval与LoCoMo同属评测基准，但LongMemEval的独特贡献在于：

1. 聚焦用户-AI任务导向对话（而非人-人对话）；

2. 覆盖知识更新和弃权能力（LoCoMo未覆盖）；

3. 历史长度可自由扩展（从115k到1.5M      tokens）；

4. 提供了统一记忆框架和具体优化建议。

6. 局限性与未来方向

  证据会话由LLM模拟：虽经人工筛选，可能仍不完全反映真实用户行为。

  评估依赖LLM-as-judge：虽与人类专家一致率高，但仍有偏差风险。

  未评估记忆删除操作：论文在伦理声明中指出，系统缺乏记忆删除机制可能损害可信度。

  商业系统评估规模有限：仅97个问题，3-6个会话，远短于LongMemEval_S。

总结

LongMemEval的核心贡献在于，它是首个全面覆盖五类核心记忆能力、历史长度可自由扩展的

聊天助手长期记忆评测基准。         其主要发现包括：

1. 当前系统远未达标：商业系统和长上下文LLM在LongMemEval上均表现不佳，下降幅度达

  30%-64%。

2. 记忆设计有章可循：通过统一框架分析，论文提出了轮次级分解、事实增强键扩展、时间感
  知查询扩展、CoN+JSON阅读等有效优化策略。

3. 阅读策略不可忽视：即使完美检索，次优阅读策略仍可导致显著性能下降。

这项工作与LoCoMo一起，为LLM记忆系统研究提供了标准化的评估标尺。您之前分析的所有

记忆方法（A-Mem、EverMemOS、ExpeL、Dynamic       Cheatsheet、HippoRAG等）都可以在
