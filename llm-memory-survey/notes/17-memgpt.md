# MemGPT: Towards LLMs as Operating Systems

> 来源文件：`memgpt.pdf` · 整理自 DeepSeek 对话阅读笔记 · [返回综述](../survey.md)

好的，我已仔细阅读并分析了您上传的论文《MemGPT: Towards LLMs as Operating Systems》。这是一篇来自 UC Berkeley 的研究工作，提出了一个受操作系统虚拟内存启发的LLM 记忆管理系统，是“LLM 作为操作系统”方向的开创性论文之一。

以下是对该论文核心内容的系统分析与总结：

## 1. 核心问题与动机


论文指出现有     LLM 面临一个根本性限制：固定长度的上下文窗口。这严重阻碍了                  LLM 在以下
场景中的应用：

  长对话：多数开源      LLM 只能支持几十轮对话，或处理短文档就会超限。

  长文档分析：法律、金融等文档常超过百万             token，远超当前模型上下文窗口。

  长程推理：需要跨多个文档、多个会话整合信息。

直接扩展   Transformer 上下文长度会带来    二次计算和内存成本；即使训练出更长上下文模型，

研究也表明模型难以有效利用长上下文（“lost-in-the-middle”）。因此，论文提出：能否在不

改变模型架构的前提下，为         LLM 提供“无限上下文”的错觉？

核心灵感来自操作系统的虚拟内存分页：应用程序看到的是比物理内存更大的地址空间，OS                           负

责在物理内存和磁盘之间分页。MemGPT           将这一思想引入     LLM：把上下文窗口当作“物理内
存”，把外部存储当作“磁盘”，让         LLM 通过函数调用自主管理记忆的分页。

2. 方法：MemGPT       的 OS  式记忆架构

MemGPT  是一个系统框架，不是新模型。它用函数调用增强固定上下文                  LLM，使其能够读写外

部数据、修改自身上下文、决定何时返回用户。

2.1 主上下文（Main   Context）

主上下文即    LLM 的提示  token，分为三部分：

  系统指令：静态部分，说明         MemGPT 控制流、记忆层级用法、函数         schema。

  工作上下文：固定大小的可读写文本块，只能通过               MemGPT  函数调用写入。用于存储用户
  关键事实、偏好、人格信息等。

  FIFO 队列：滚动消息历史，包括用户消息、助手回复、系统消息（如内存警告）、函数调用
  输入输出。队列第一个位置存放被驱逐消息的递归摘要。

2.2 外部上下文（External  Context）

外部上下文是上下文窗口之外的信息，必须显式移入主上下文才能被                    LLM 使用。包括：

  Recall Storage：消息数据库，存储所有历史消息。

  Archival Storage：任意长度文本对象数据库，支持向量搜索。

2.3 队列管理器（Queue    Manager）

负责管理   FIFO 队列和  recall storage：

  新消息到达时追加到       FIFO，触发  LLM 推理。

  将消息和生成输出写入       recall storage。

  当 token 超过“警告阈值”（如    70% 上下文），插入系统警告，提示          LLM 即将驱逐。

  当 token 超过“刷新阈值”（如    100%），驱逐部分消息（如        50%），生成新的递归摘要。被

  驱逐消息仍存于     recall storage，可通过函数调用读回。

2.4 函数执行器（Function   Executor）

LLM 的输出被解析为函数调用。函数执行后结果反馈给处理器，形成闭环。MemGPT                      提供自管

理记忆的函数，例如：

  搜索  recall storage / archival storage；

  读写工作上下文；

  修改自身记忆；

  控制是否立即返回控制权。

2.5 控制流与函数链

MemGPT  由事件触发推理：用户消息、系统警告、定时事件等。函数链允许                    LLM 连续调用多

个函数，再返回用户。通过特殊标志            request_heartbeat=true ，LLM 可在函数执行后立即获得
控制权，继续下一步；否则让出控制，等待下一个外部事件。

3. 实验与主要结果

论文在两个长上下文领域评估         MemGPT：对话智能体和文档分析。

3.1 对话智能体

数据集：Multi-Session Chat（MSC），每段对话      5 个会话，每会话约十几条消息。论文新增

第 6 个会话，包含一个      QA 对。

任务一：Deep    Memory Retrieval（DMR，一致性）

  问题必须依赖之前会话才能回答。

  结果：

    GPT-3.5 Turbo：38.7% → +MemGPT：66.9%

    GPT-4：32.1% → +MemGPT：92.5%

    GPT-4 Turbo：35.3% → +MemGPT：93.4%

  MemGPT  显著优于固定上下文基线（基线只看到过去五段对话的有损摘要）。

任务二：Conversation  Opener（参与度）

  评估生成的开场白是否利用长期记忆、是否吸引人。

  结果：MemGPT    在 SIM-1/SIM-3 上超过人类开场白；与人类开场白的相似度（SIM-H）低
  于人类，但整体表现接近甚至偶尔超过人类。工作上下文存储信息对生成吸引人开场白至关

  重要。

3.2 文档分析

任务一：多文档问答

  使用  NaturalQuestions-Open 检索器-读者设置。

  固定上下文基线性能受检索器上限限制；MemGPT              可通过多次分页检索，突破上下文窗口限
  制。

  结果：MemGPT    性能不受上下文长度增加影响；截断基线随文档数增加性能下降。

  MemGPT  用 GPT-4 最佳；GPT-3.5 因函数调用能力弱表现较差。

任务二：嵌套键值检索（Nested        KV）

  值本身可能是键，需要多跳查找。

  结果：

    GPT-3.5 基线在 1 层嵌套即   0%；

    GPT-4 / GPT-4 Turbo 基线在 3 层嵌套时 0%；

    MemGPT  + GPT-4 不受嵌套层数影响，能通过多轮函数查询完成多跳查找；

    MemGPT  + GPT-4 Turbo / GPT-3.5 在 2 层后性能下降。

4. 关键洞察

1. 虚拟上下文管理有效：通过分层记忆和函数调用，固定上下文                 LLM 可以处理远超窗口长度的
  文档和对话。

2. 自管理记忆：MemGPT     自主决定何时读写、何时驱逐、何时返回用户，无需人工干预。

3. 函数调用能力是关键：GPT-4      的函数调用能力强，MemGPT        效果最好；GPT-3.5   能力弱，

  效果明显下降。

4. 分页与多步检索：MemGPT      能通过多轮检索/分页突破检索器单次返回限制，实现多跳查
  找。

5. OS 类比成立：主上下文≈RAM，外部存储≈磁盘，队列管理器≈页面调度，函数调用≈系统

  调用。

5. 与您之前分析论文的关系

| 论文 | 核心焦点 | 与 MemGPT 的关系 |
| --- | --- | --- |
| MemGPT | OS 式虚拟上下文管理：分层记忆 + 函数调用 + 事件控制流 | 本工作自身，是 LLM 记忆操作系统方向的先驱 |
| Mem0 | 生产级长期记忆：提取 + 更新 + 图记忆 | Mem0 更偏工程化记忆提取与更新；MemGPT 更偏 OS 式分页与自管理 |
| A-Mem | Zettelkasten 式原子笔记链接与演化 | A-Mem 是结构化外部记忆；MemGPT 是分层存储与函数调用 |
| EverMemOS | 三阶段记忆生命周期 | EverMemOS 受认知科学启发；MemGPT 受操作系统启发 |
| MEM1 / MEMAGENT | RL 训练模型内化记忆，恒定内存 | MemGPT 是外部系统，不改变模型参数；MEM1/MEMAGENT 通过 RL 训练模型自身记忆能力 |
| HippoRAG / HippoRAG 2 | KG + PPR 多跳检索 | HippoRAG 是检索端图方法；MemGPT 是通用 OS 式记忆管理 |
| Dynamic Cheatsheet | 测试时动态更新提示上下文 | Dynamic Cheatsheet 更新提示中的记忆；MemGPT 管理多级存储与函数调用 |
| ExpeL | 经验学习：提取洞察并回忆 | ExpeL 离线提取洞察；MemGPT 在线自主管理 |
| LongMemEval / LoCoMo | 长期记忆评测基准 | MemGPT 是早期系统；这些基准后来用于评估记忆能力 |

关键区别：MemGPT     是“系统层”工作，不训练模型、不修改架构，而是通过函数调用和分层存储赋予LLM 虚拟无限上下文。
它是后续Mem0、MemOS、MemoryOS、A-Mem      等记忆系统的重要思想来源。

6. 局限性与未来方向

  依赖函数调用能力：GPT-3.5      等较弱模型函数调用能力差，MemGPT          效果显著下降。

  检索器质量影响大：文档        QA 中，若检索器排序噪声大，MemGPT         可能过早停止分页。

  控制流与记忆策略启发式：队列驱逐、警告阈值、摘要生成等策略为手工设计，未端到端优
  化。

  多步延迟与成本：函数链式调用增加推理轮次和延迟。

  安全与隐私：长期记忆存储用户信息，可能带来隐私泄露风险。

  未来方向：将     MemGPT 应用于更多大规模/无界上下文领域；集成数据库、缓存等不同记忆

  层技术；改进控制流与记忆管理策略。

总结

MemGPT  的核心贡献在于，它首次系统性地将操作系统虚拟内存思想引入                   LLM，提出了“虚拟
上下文管理”框架。      通过分层记忆（主上下文        + 外部上下文）、队列管理器、函数执行器和事

件驱动控制流，MemGPT       让固定上下文    LLM 能够处理长文档、长对话和多跳检索，在            DMR

任务上将   GPT-4 从 32.1% 提升至  92.5%，在嵌套   KV 任务中实现不受嵌套层数影响的检索。
这项工作开创了“LLM      作为操作系统”的研究方向，为后续          Mem0、MemOS、EverMemOS    等

记忆系统奠定了重要基础。
