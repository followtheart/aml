# 評測與驗收設計

狀態：測試計畫；目前沒有新系統執行結果。

## 1. 必須回答的問題

雙側聯想是否比只擴展一側更能找回必要來源？提升是否值得新增的寫入成本、搜尋成本及儲存空間？精判是否能排除聯想造成的錯誤連接，同時保留反證與必要的部分證據？

## 2. 四組消融與舊系統基線

| 組別 | 寫入側 | 搜尋側 | 原始事件精判 |
|---|---|---|---|
| C00 | A₀ | B₀ | 相同 |
| C10 | A₀…Aₘ | B₀ | 相同 |
| C01 | A₀ | B₀…Bₙ | 相同 |
| C11 | A₀…Aₘ | B₀…Bₙ | 相同 |
| legacy | 固定 commit 的 memory_system | 固定設定 | 原有管線 |

四組保持事件切分、來源、embedding 模型、精判模型、候選上限、最終 top_k 與輸出預算一致；唯一主要變數是啟用哪些視角。增加 C11-without-verification 作研究診斷，只計算噪聲，不能作正式服務模式。

另外提供等總成本比較：在相同搜尋延遲／費用上限下，比較雙側擴展與提高單側召回量。否則只增加計算量也可能被誤讀為架構優勢。

## 3. 資料與標註

沿用倉庫可取得的 LoCoMo／PersonaMem 資料與已有來源標註，記錄資料版本、切分與使用限制。依使用者／會話隔離開發與測試集，不使用測試題或答案生成寫入聯想。

人工案例至少包含：中文同義詞、跨語言、事件到用途、罕見實體、否定、朋友與使用者混淆、引述角色、條件句、假設、時間修訂、同名不同人、無答案、大量同主題噪聲、反證、必要的多事件組。

標註單位為原始 source span／event 與 query 的關係，不以模型衍生視角作 gold。gold 同時標記 direct／partial／contradicting／irrelevant；多事件題標必要組合。

## 4. 逐階段指標

| 階段 | 指標 |
|---|---|
| 寫入 | 原始來源覆蓋率、有效錨點率、人物／否定保真率、每事件視角數、重複率 |
| 召回 | Source Recall@64、完整證據組 Recall、僅由擴展救回的來源數 |
| 粗排 | Recall@16、按不同 query facet 的覆蓋、候選去重前後數量 |
| 精判 | 相關 precision/recall、反證 recall、人物／時間誤配率、uncertain 比例 |
| 打包 | 最終 evidence precision/recall、完整引文率、完整證據組保留率 |
| 下游 | 固定回答模型與提示詞的任務準確率；與記憶召回指標分開 |
| 成本 | Add／Search p50/p95、每階段模型次數與 token、費用、索引 bytes/event |

事件相關性不等於答案充分性；若 gold 缺少完整來源，不用 answer accuracy 反推所有檢索錯誤。每個漏召回題區分：未寫入、視角無匹配、索引漏召回、候選截斷、粗排淘汰、精判誤拒、打包省略、回答誤用。

記錄樣本數、按使用者分組的配對差異及 bootstrap 區間。先在開發集固定參數，再只執行一次測試集比較；測試後調參需改用新保留集。

## 5. 功能與故障驗收

- 雙側視角能找回原文詞面不重疊的事件；精判輸入確實只包含原始 A/B。
- 新增 20 個完全相同的視角不能增加事件票數或擠占不同事件配額。
- 相同主題、不同人物的誤連接被精判拒絕；反證仍能返回。
- 同 request 重送不新增資料；不同 payload 使用同 request_id 回報衝突。
- 租戶隔離適用所有索引、trace 與快取；相同事件文字不能跨使用者去重而混淆歸屬。
- 修訂、歷史查詢、刪除、遺忘與進行中的搜尋具一致性測試。
- 擴展失敗仍可原文召回；精判失敗不回報 verified；全失敗不回報普通 not_found。
- 錯誤引用、錯誤 ID、格式錯誤、向量維度／版本錯誤均有明確失敗狀態。
- 長原文不能因截斷失去否定或人物歸屬；無法保留必要上下文就標記未完成。
- 小資料集精確掃描作 ANN recall 對照；固定容量下測不同事件數與視角數。
- 達期限、token、候選或字節上限即停止，不循環擴展或重試。

## 6. 採用準則

硬性門檻是來源可追溯、隔離／刪除正確、無偽造引用、未精判結果不冒充通過。效能採用條件要在開發集比較後預先固定：例如 C11 對最強單側方案的 Source Recall 改善，同時 final precision 不顯著下降，p95 與總成本在產品預算內。

若 C10 在相近品質下更便宜，可以將搜尋擴展限制為按需啟用；若 C11 的候選噪聲抵銷收益，減少抽象／用途視角，不能只增加後段模型補救。測試結果決定預設策略，不預設雙側一定勝出。
