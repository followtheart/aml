# v5 真實模型驗證：局部改善，尚未證明雙側優勢

日期：2026-10-24。已完成實作、92 項測試、四組流程測試，以及新的 12 段完整 LongMemEval 歷史之 96 次搜尋／192 筆交叉回答評測。

**本輪雙側端到端表現提高，但最佳單側同樣可達 75%。不能宣稱雙側擴展本身已帶來可靠優勢，也不能宣稱新的候選保留策略已有效。** 前 16 名覆蓋改善，精判仍誤刪前提；新回答器也不是所有情境都更好。

## 改了什麼

- 相對日期只綁定其原始來源時間；增加有限英文日／週／月／年距離計算、年月區間與約略程度，避免把年份捏造成某一天，拒絕不支援的複合／小數／負數尾段誤算。
- 原文重排使用原始問題及各來源時間，精判要求保留同一事件的時間上下界、序數身份及互補前提，維持逐字引用與事件歸屬校驗。
- 停用預設的無條件獨有來源槽。新策略只補足問題明示且池中缺少的實體、引號短語或年份，要求原文語義排名前 32 名且不能損失已有線索，最多替換末兩名；精判仍最多 16 個事件。四組用相同規則。
- 新增可選 `/answer`：去重完整原文、來源時間、局部日期註解、引用及缺失前提；日期差計算清楚標為陳述日期差。答案不寫回記憶，引用編號合法不等於語義正確。並發更新／刪除會使回答失效。

實作位於獨立的 `memory_connection/app`，不匯入 `memory_system`。評測適配器才讀取舊回答提示詞／模型配置，沒有修改舊系統源碼。設計細節見 [GROUNDING_V5.md](GROUNDING_V5.md)。

## 新樣本與公平性

舊 LoCoMo10 的全部會話已用過，本輪首次使用作者發布的 [LongMemEval 清理版](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned)，固定 revision 與 SHA-256。固定種子 20261027，抽取 4 題時間推理、4 題跨會話、2 題知識更新、2 題單會話；12 個獨立歷史、575 個互不重複 session ID、5,971 則消息，無損切成 6,762 個事件。保留所有干擾會話，沒有按答案篩選內容。這是專案未測資料，不代表模型訓練時未見過公開資料。

兩版共用 C0／C1 寫入索引、相同查詢視角及向量；版本前後的粗候選順序全部相同。採用 GPT-4o-mini、text-embedding-v4（256 維）與 qwen3-rerank；top_k=10、證據 24,000 bytes、精判 16 事件／2 批。每份搜尋包交叉使用舊 v4 與新 v5 回答器，同一 Judge 評分。正式評分前凍結程式及設定；看到新題結果後未修改搜尋、精判或回答器，也未重跑失敗答案。

資料集無時區，來源時鐘一致視為 UTC。兩段歷史包含提問同日但鐘點較晚的來源，其中一段含標註答案會話；主結果保留發布資料，另列排除兩段的敏感度。資料與程式雜湊、抽樣及續跑紀錄均保存在 run 目錄。

## 準確率：原始 Judge 與全部答案覆核

原始 Judge 在 192 筆答案中出現明確誤判。例如參考明許「2 天或含末日 3 天」，Judge 卻把五月十五至十七日的 2 天判錯；也把自相矛盾的先後比較判對。因此保留原始分數，另由本代理事後逐答覆核全部 192 筆，記錄 24 筆差異。覆核不是盲測或獨立人類標註，不取代預先凍結的主評分；兩者一起呈現。

覆核要求完整符合題目及參考容差，拒絕錯誤數值和自相矛盾的結論。它衡量答案與參考一致性，不代表所有額外敘述都已獲原文證明。逐筆標籤、理由與答案雜湊見 `answer-audit.json`；原始答案／Judge 理由完全保留於 `results.jsonl`。

| 擴展模式 | 原始 Judge：v4 → v5 | 逐答覆核：v4 → v5 | 覆核配對勝／負 |
|---|---|---|---|
| C00 不擴展 | 7/12（58.3%） → 8/12（66.7%） | 7/12（58.3%） → 8/12（66.7%） | 1／0 |
| C10 僅記憶擴展 | 6/12（50.0%） → 7/12（58.3%） | 6/12（50.0%） → 7/12（58.3%） | 2／1 |
| C01 僅查詢擴展 | 7/12（58.3%） → 8/12（66.7%） | 8/12（66.7%） → 9/12（75.0%） | 2／1 |
| C11 雙側擴展 | 5/12（41.7%） → 9/12（75.0%） | 6/12（50.0%） → 9/12（75.0%） | 3／0 |

主比較固定為「v4 檢索＋v4 回答」對「v5 檢索＋v5 回答」。覆核後 C11 提高 25 個百分點，3 勝 0 負；精確配對 sign test p=0.25，按歷史 bootstrap 的差值 95% 區間為 [0, 50] 個百分點。12 題、一次模型生成不足以建立統計上的穩健提升；192 筆不是 192 個獨立樣本。

新版 C11 與最佳單側 C01 同為 9/12，配對 1 勝 1 負、p=1.0，差值區間 [-25, 25] 個百分點。原始 Judge 看似 C11 領先 C01 一題，覆核後該優勢消失。排除兩個同日鐘點異常歷史後，C11 仍多答對 2/10，p=0.5。另排除任一版本搜尋降級或精判錯誤的配對，C11 剩 7 題，3 勝 0 負、p=0.25；這是事後子集，不能取代全樣本。

固定舊回答器，C11 從 6/12 到 10/12；固定新回答器，C11 從 7/12 到 9/12，表示檢索／重排／精判組合變更確有樣本內改善。可是使用新版 C11 證據時，新回答器為 9/12，低於舊回答器 10/12。新回答器只作可選實驗功能，不能宣稱全面優於舊版。

這些交叉結果不能進一步分離日期註解、重排提示、精判提示及上下文排列各自的因果效應；模型也有單次生成差異。沒有將全部提升歸因於雙側聯想或某個提示詞。

## 證據究竟在哪裡流失

下表是每題標註消息切塊召回率的宏平均，並非所有返回內容的 precision；標註消息不一定包含推理需要的全部鄰近前提。兩版四組粗候選覆蓋全部為 100%。

| 模式 | 前 16 名 v4 → v5 | 精判後 v4 → v5 | 最終原文 v4 → v5 |
|---|---|---|---|
| C00 | 91.67% → 95.83% | 87.50% → 91.67% | 87.50% → 91.67% |
| C10 | 95.83% → 100.00% | 79.17% → 75.00% | 79.17% → 75.00% |
| C01 | 95.83% → 95.83% | 83.33% → 87.50% | 83.33% → 87.50% |
| C11 | 91.67% → 100.00% | 83.33% → 79.17% | 83.33% → 79.17% |

C11 的前 16 名覆蓋從 91.67% 提高到 100%，但精判後由 83.33% 降到 79.17%。因此本輪主要瓶頸已不是 C11 候選池的標註證據不足，而是精判與事件綁定。終端裁剪沒有造成這個平均下降。

舊 C11 保留槽在 12 題共提升 12 個事件，零次補入新標註來源，且在追蹤者題踢掉起始數量的標註來源。停用這個強制槽有明確理由。新條件式槽在 48 次新版搜尋中觸發 **0 次**，所以只能說避免強制置換，不能說新槽已展示召回收益。

本次所有標註證據在單側粗候選中已可找到，C11 相對兩個單側候選聯集的獨有標註證據為 **0**。本樣本無法驗證「只有雙側聯想才找得到」這個機制，也無法驗證新槽會救回那類證據。C11 最終比兩個單側輸出聯集多出的標註消息只出現在親子先後題，該題新版回答依然自相矛盾。

## 具體成功與失敗

- **模型製作先後 `gpt4_c27434e8`**：兩個來源原本都召回；舊 C11 把三週前說成比一個月前更早，新 C11 正確回答日本零式先開始。這是讀取／日期關係改善的案例，並非新增獨有召回。單次交叉回答仍有波動。
- **露營天數 `gpt4_1d80365e`**：開始和返回原文在新舊 C11 都存在。新精判將返回保留為 partial、開始保留為 relevant；舊回答器在舊證據上棄答，新回答器能回答 2 天。原始 Judge 錯誤否定新答案，覆核恢復為正確。這展示完整讀取與日期計算的價值，但並未證明舊精判曾丟掉這題的時間前提。
- **追蹤者增量 `a11281a2`**：新版起始 250 人的原文已進第 15 名，卻被精判以「在談抽獎，不是追蹤者增長」判 irrelevant；終點 350 人被誤認為直接回答增量。兩個回答器、四組全部答成增加 350 人，正解為 100。多跳起點保留仍失敗。
- **SaveMart 回饋 `9aaed6a3`**：新版 C11 的 1% 回饋規則已在第 4、13、14 名，仍被判成購物計畫而無關；消費 75 元被當成可直接回答回饋。新回答器錯答 75 元，正解 0.75 元。僅增加引用或缺失前提欄位不能阻止這種錯誤。
- **親子先後 `gpt4_fe651585`**：Rachel 與雙胞胎的標註消息在第 7 名仍被判「沒有育兒資訊」而刪除。新版答案先說 Alex 較早，又說無法比較 Rachel；原始 Judge 給對，但覆核視為矛盾。其他組還將另一對孩子的一歲生日錯綁到 Rachel。時間前提與人物事件對齊仍未解決。
- **最近家庭旅行 `9ea5eabc`**：新版 C11 正確選 Paris；C01 仍答 Hawaii。因此新版 C11 與 C01 各有對方答錯的題，總分相同。標註來源覆蓋只是代理指標：較舊旅行也被標註，保留或刪除它與答案正確性並非單調關係。

舊 LoCoMo 開發案例中，六題最後四題答對，第三部劇本的事件時間綁定仍錯、圖片書名缺失仍無解；這些開發分數沒有混入新測試成績。

- 評分前有一次通用日期數值邊界與 JSON 外框預算修正；當時尚未搜尋或評分任何新題，前後快照與變更雜湊保存在 `pre-evaluation-freeze-1/`、`resumptions.jsonl`。另一次為不改程式的超時續跑。

從倉庫根目錄執行：

