# HTTPS 空记忆修复与验证

曾部署到 `https://www.dustman.com.cn:443` 并完成以下验证。随后于 2026-10-24 按要求停用本服务、取消开机启动，并恢复 `memory_system` HTTPS 服务；修复代码保留。相同完整 61 题重新入库评测，空结果 **43/61 → 25/61**（70.5% → 41.0%），减少 18 次；正确答案 **11/61 → 13/61**（18.0% → 21.3%）。修复了可复现的实现错误，但没有消除所有空结果，当前成绩仍低于旧 memory_system 历史基线 19/61。

## 已修复的问题

1. **单个超长候选使整批重排失效。** 原代码发现任一候选超过 6000 bytes，就返回整个粗排列表，重排调用数为 0。现在对超长文档做保留来源角色、时间和字符范围的无损分片，按片段最高分排序原事件；精判仍读取原始事件。验证集中 61 次搜索全部执行了重排，无 DocumentOverflow 整批退回。
2. **选项前提缺少确定的召回入口。** 原始问题可能只有泛化的推荐需求，关键个人前提藏在选项中。现在各选项作为明确标记的待核实假设参与检索和重排，精判检查其原文依据；选项不写入记忆，不被当作事实或引用来源。
3. **字节分批后只处理两批，丢弃已选候选。** 16 个原始事件可能因 24000-byte 上限分成三至四批。默认最多批次数由 2 改为 8，保持 16 个候选上限、单批字节上限和总截止时间。此次 61 题没有 batch_budget 遗漏，共 205 次精判调用，973/976 个候选得到有效判定；另外 3 个仍因引用不合法而被拒绝。
4. **过量有效引用导致整条相关记忆被丢弃。** 真实调用发现模型返回 relevant/partial，却列出 29–35 个句子引用，触发 maxItems=8。现在只有所有引用均属于该事件、逐字准确，且能无损合并为最多 8 个相邻片段时才保留。未知引用、跨事件引用、不相邻且仍超过上限的引用继续失败。
5. **HTTPS 适配层丢弃诊断信息。** 原有 coverage_manifest 现在包含重排/精判计数、降级原因、验证错误及 empty_reason，不改变顶层请求/响应契约，不输出内部提示词正文。

## 完整 HTTPS 结果

使用之前同一 PersonaMem-v2 队列：474 条消息、29 个 Add 请求、61 题。仍采用旧基线冻结的 GPT-4o-mini 回答器和已记录配置，top_k=50、证据预算 32000 bytes。直接调用部署在 443 的新接口并验证 TLS 证书及域名。

| 指标 | 修复前 | 最终部署版本 |
|---|---:|---:|
| 空记忆查询 | 43/61 | 25/61 |
| 正确答案 | 11/61 | 13/61 |
| 第一会话正确答案 | 5/31 | 8/31 |
| 第二会话正确答案 | 6/30 | 5/30 |
| 搜索平均耗时 | 13.23 秒 | 23.36 秒 |
| 搜索 P95 | 17.08 秒 | 30.36 秒 |
| HTTP / 终止性回答错误 | 0 / 0 | 0 / 0 |
| 完整参考原文到达返回来源 | 6/48 | 10/48 |
| 完整参考原文到达回答器目录 | 4/48 | 5/48 |

逐题比较：22 个原空查询恢复非空，同时 4 个原非空查询变为空；答题 3 胜、1 负。重新入库和模型输出存在随机性，这不是严格的单因素因果实验。延迟增加来自实际执行重排和更多有界精判。

剩余 25 个空结果中，24 个的已检查候选被判为无关，1 个还包含引用校验失败。**不能据此断言数据库中没有相关记忆**：粗排候选和精判数量仍有上限。全部搜索仍报告 incomplete/partial，避免把有界候选检查误报为完整证据覆盖。后续若要进一步改善，需要提高候选相关性、来源覆盖及回答器证据利用，而非无条件返回粗排内容。

## 其他验证与取舍

- 最终代码 111 项测试通过，包括长文档分片、中文/emoji 原文重组、晚批次证据保留、选项入口、相邻引用无损合并及跨事件拒绝。
- 真实 HTTPS 合成回归通过：含超长干扰消息时能找回选项所需的花生过敏记忆；无关问题及其他用户查询保持为空。
- 两个真实会话全部 474 条原文逐字入库一致；61 题无遗漏、无重复，请求参数与历史基线一致。
- 曾在隔离副本尝试“首轮无有效证据时，在剩余预算内检查后续 16 个候选”。完整、索引逐字节固定的 HTTPS 复测为 26 个空结果、13/61 答对，未比部署版本的 25 个空结果、13/61 改善，因此**没有启用或合入这项补查**。隔离复测仍会重新生成查询和模型判断，不能视为完全冻结的逐阶段因果实验。
- 该补查首次隔离运行因 systemd EnvironmentFile 覆盖测试库路径而读到主复测测试用户，后续受清理影响；已明确标为无效并排除。修正后从运行进程环境确认实际隔离数据库，核对 474 个事件/视角/向量完全一致，再完成完整复测。评测器增加了删除后实际数据库核验及无效运行拒绝逻辑。
- 修复验证结束时正式服务监听 443，PID 3301988，systemd active/running；该进程已在后续恢复旧服务时停止。两轮有效评测的测试用户已清理；临时服务已停止。原始实验档案保留在本地、权限 0700、Git 忽略目录内。
- memory_system 的 731 个已跟踪文件哈希未改变。修复验证期间未启用旧服务；后续按要求恢复旧服务时再次核对文件哈希未变。
