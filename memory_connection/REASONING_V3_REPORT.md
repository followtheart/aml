## 失敗發生在哪裡

| C11 指標 | v2 | v3 |
|---|---:|---:|
| 粗候選來源召回 | 91.26% | 91.26% |
| 前 16 名來源召回 | 89.58% | 83.36% |
| 精判接受來源召回 | 87.39% | 75.46% |
| 最終來源召回 | 87.14% | 75.46% |
| 最終明確引用標註來源 | 86.89% | 68.98% |
| 多跳題答對數 | 7/7 | 5/7 |
| 日期題答對數 | 3/4 | 3/4 |

來源級重排在開發案例能救回上下文國名，但未測會話的 C11 前 16 名覆蓋反而下降。更複雜的精判協定也伴隨更多錯誤：八組中，before 144 筆只有 7 筆查詢含精判錯誤，after 增至 43 筆；無效裁決由 0 個增至 47 個，無效引用由 7 個增至 30 個。這是整組修改的觀察結果，沒有額外消融可將每一個錯誤歸因於單一元件。

路徑型保留槽在 23 題提升了 36 個事件，但這些事件中 **沒有標註來源**。只有「路徑同時用到兩側擴展」並不能證明它是有用的獨有證據。實際四組候選比較中，唯一 C11 候選獨有的標註來源（conv-49／19 的 D3:10）仍未出現在最終證據中。

另外，日期題在 C00、C10、C01 從 3/4 提高到 4/4，表示日期處理值得單獨保留，但不能抵消其他階段退步。開發案例「城堡夢境」即使已返回具體原文，Answer 仍偏向概括描述；不能把它宣稱成端到端修復。
