## 核心流程證據

可控 fixture 中，原始 A「甲源」與原始 B「乙需」對應正交向量且沒有詞面重疊。兩側各自擴展到「共同橋接」後，A₁ 和 B₁ 才匹配。

| 模式 | 召回事件 | 返回證據 | 精判輸入含聯想文字 |
|---|---:|---:|---|
| C00：不擴展 | 0 | 0 | 否 |
| C10：僅記憶擴展 | 0 | 0 | 否 |
| C01：僅搜尋擴展 | 0 | 0 | 否 |
| C11：雙側擴展 | 1 | 1 | 否 |

另有獨立測試驗證原文直達、A₁↔B₀、A₀↔B₁ 路徑可以各自成功；以上四組的零結果是特定 fixture 的設定，不代表單側擴展沒有作用。

精判 fixture 會拒絕「朋友甲源」的誤連接；測試確認該事件先進召回候選，再被精判排除。測試同時檢查精判收到的是原始問題、帶角色與來源的原文，不含聯想視角或粗排分數；最後輸出仍是原文。

## 覆蓋範圍

- 四種擴展配置、原文與聯想橋接、重複視角去重、按事件候選上限。
- 原文精判拒絕誤連接、保留反證、部分證據狀態、引文逐字校驗及 Unicode 範圍。
- 原始消息與相鄰上下文角色、來源時間參考、版本替換、歷史與未來有效區間。
- 使用者隔離、敏感／抑制來源、冪等衝突、原子寫入、多消息中途失敗回滾。
- 遺忘期間的搜尋失效、遺忘期間的寫入防止復活、最小 revision 校驗。
- 擴展與 embedding 降級、精判超時、部分批次失敗、錯誤 ID、偽造引文、語境及輸出預算。
- HTTP 鑑權與 Add／Search／Purge 契約、embedding 空間指紋、正式 provider 必填配置。
- 透過 HTTPX MockTransport 驗證正式 API 適配器的 JSON 請求與 embedding 回傳順序。
