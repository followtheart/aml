已將單選題答案入口改為「逐選項來源檢查 → 個別前提及完整選項核對 → 獨立遺忘約束 → 限定候選選擇」。五道目標題在固定證據包下重複三次皆答對；全 26 題固定包回放由封存答案的 **9/26（34.62%）** 變為 **11/26（42.31%）**。仍有三題退步，這次修補不能視為答案端所有語義問題均已解決。

**修補的行為與範圍**

- `app/eval_scoring.py` 的單選題入口接入 `app/answer_choice.py`，政策版本為 `verified-source-choice-v1`。多選、排序、binary、refined 與 rubric 評分維持各自的既有入口。
- 原文目錄來自答案包實際可見的 `sources`，保留原始角色、時間、訊息定位及所屬記憶。摘要不能冒充使用者原話；assistant 訊息不能獨立證明使用者的個人經歷。
- 每個選項列出個人前提、逐字引文及敘述主體。本地檢查引文和選項片段，保留第三人、假設、否定及興趣與實際經驗的區別；不能只相信模型填寫的角色。
- 獨立核對同時包含每個完整選項與初判有支持的個別前提。即使選項被標成一般建議，也必須接受完整選項檢查，避免漏掉個人前提。任何否定只會降級，不能把未支持的選項重新提升。整體建議合理，不能取代個別歷史前提的證據。
- 遺忘規則獨立處理：按來源中的原始句子分拆、保留句子位置及外層歸屬，再對具有主題交集的選項逐一判定。無關前文、另一條規則，以及「Don't forget」提醒不再稀釋或取消後面的真實遺忘请求。
- 最終模型只能在已通過檢查且未被約束排除的選項集合內選擇；只有一個合格選項時直接採用。平手判斷保留原文、來源時間及問題日期。沒有合格選項或模型輸出持續無效時明確記錄失敗，不退回未經驗證的直接答案。
- 記錄每次階段呼叫的 prompt SHA-256、來源目錄、逐選項判定、約束、候選集合與選擇方式。新增 `scripts/replay_answer_choice.py` 可直接重放真實 `evaluate` 入口，保存完整請求與模型回應；Gold 僅用於回應後評分。

**驗證、成本與失敗邊界**

- 全部 **32/32 組、532 項離線測試通過**，其中新增答案端測試 61 項。另已通過獨立程式審查與 `git diff --check`。
- 保存修補前的真實 RED 證據，涵蓋個人前提誤標成一般建議、只驗證部分前提、多條遺忘規則與普通前文混合；修補後的回歸測試均通過。也涵蓋跨空白段落的第三人引用、混合提醒與遺忘句、問題日期、時間戳、Gold 隔離及模型選出集合外字母。
- 最終 26 題使用 71 次 provider 呼叫、146,029 tokens，平均約 2.73 次／題，實際範圍 2–4 次。五題重複三次使用 33 次呼叫、86,124 tokens。這些數字僅為最後驗證，不含保留在目錄中的開發中試跑。
- 無既有呼叫端預算時，答案端設 240 秒、8 次 provider 呼叫、128,000 tokens；有既有預算時共用。每階段最多一次格式修復，傳輸重試也消耗預算。增加驗證會提高成本；本次沒有量測可靠的端到端延遲分布。
- 結構容量為最多 26 個選項、每選項八個前提，合計最多 234 項語義核對；約束配對輸出上限 104。超限或持續無效會明確失敗，不能假設任何大小的選項與規則組合都可處理。
- 約束的主題交集與主體字面規則是局部防護，不是完整語義證明。模型仍可能錯判支持、一般建議或約束範圍；這次結果不支持全面放寬這些防護。
