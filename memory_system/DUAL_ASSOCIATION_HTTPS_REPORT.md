# 双侧联想完整 HTTPS 配对测评

2026-10-24。相同 61 题、相同模型和预算，基线答对 **17/61（27.9%）**，双侧联想答对 **13/61（21.3%）**，下降 **6.6 个百分点**；3 题改善、7 题退步。两组均无终止错误。本轮未体现收益，继续保持联想开关默认关闭，未重启或改变生产 443 服务。

## 方法与范围

两组分别从空库开始，经真实 HTTPS Add 写入相同的两个完整会话、474 条原始消息（29 批），然后逐题执行 HTTPS Search、主审、证据打包和本地 Answer/评分。两组独立数据库与本地 TLS 服务，端口 18604/18605；验证证书，不关闭 TLS 校验。所有 61 题都计入分母，没有按成败删题或重跑替换。

两组冻结的 728 份源码/资源文件相同。LLM 为 gpt-4o-mini，embedding 为 text-embedding-v4（256 维），CE 为 qwen3-rerank；既有设置与此前补充验证基线一致。仅实验组将 `AML_ASSOCIATION_WRITE`、`AML_ASSOCIATION_RECALL`、`AML_ASSOCIATION_QUERY` 从 0 改为 1；没有采用候选诊断中放宽后的预算。全部请求的实际版本与设置均通过审计。

这是新入库的单次配对实验，记忆抽取、主审和回答均有随机波动，两个会话内的问题也并非独立样本。不能将全部差异精确归因于联想机制。作为描述性配对统计，McNemar 双侧精确 p=0.34375，不足以宣称稳定退步或普遍无效，但当前结果不支持启用。评分沿用本项目本地协议，不是官方排行榜分数。

此前同队列基线是 19/61（31.1%）；本次重新入库、重新答题后的基线为 17/61。判断本轮差异应比较 **17 与 13**，不将旧 19 分直接作为本轮控制组。

## 原文交付与错误

以下是“至少一条完整参考用户原文可见”的题数，属于诊断，不等于答案有充分支持。48 题在输入历史中存在完整参考原文。

| 阶段 | 基线 | 双侧联想 |
|---|---:|---:|
| 粗排 | 45 | 46 |
| 精排 | 29 | 29 |
| 主审输入 | 27 | 26 |
| 主审选中 | 26 | 23 |
| 最终阅读目录 | 26 | 26 |
| 最终阅读目录完整覆盖可用参考集合 | 21 | 24 |

最终目录覆盖的参考回合数为 36→40，但答题分数下降。这说明“送达更多原文”没有自动转化为答题收益。Q306 从交付完整参考变为未交付；Q318、Q336 两组均交付完整参考，实验组仍答错；Q337 实验组新增完整参考交付，却在后续证据判断中答错。这些是阶段定位，尚未证明具体语义错误的唯一成因。

原始错误全部保留：基线 Add/Search/答题供应商错误为 1/0/1 次，实验组为 3/1/1 次；程序的既有重试/恢复流程均未产生终止错误。实验组 Q298 主审出现一次 LLMError（供应商 HTTP 500）。答题内部 witness 校验/调用失败分别为 2/10 次，与供应商传输错误单独记账；内部失败不是 2/10 道终止答题错误。
