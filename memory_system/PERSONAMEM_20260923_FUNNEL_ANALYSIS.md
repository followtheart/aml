**漏斗二：题目作答，定位可观测失分出口**

```text
26 题都有搜索返回
  ├─ 14 题：无可选项 → ValueError → 空预测 → 0 分
  └─ 12 题：输出有效字母

       └─ 5 题：Gold 在可选集合中
            ├─ 4 题：最终选择其他选项 → 0 分
            └─ 1 题：Q9 选对 → 1 分
```

| 指标 | 数值 | 含义 |
|---|---:|---|
| 有答案率 | 12/26 = 46.15% | 14 题失败不是“模型选了错误字母” |
| Gold 最终准入率 | 5/26 = 19.23% | Q9、Q10、Q13、Q14、Q17 |
| Gold 准入后的选择命中 | 1/5 = 20.00% | 是条件命中率，不是上游修复收益预测 |
| 已作答题准确率 | 1/12 = 8.33% | 即便排除空答，选择质量也很低 |
| 总准确率 | 1/26 = 3.85% | 与用户提供结果一致 |

这是互斥的**末端失分分类**，不是唯一根因归属：例如 Q14 同时有证据精排流失和最终选错，Q8 同时有格式回退与约束误杀。

**首要问题：前提抽取失败后，整题个人证据被清空**

`eval.choice_support` 首次成功 8/26，首次 invalid 18/26；18 次 repair 只有 1 次成功。因此，最终有 9 题取得结构上可接受的抽取结果，17 题进入 `answer_support_fallback=generic_only`。注意“结构可接受”仍不等于语义正确。

[answer_choice.py](app/answer_choice.py) 的 `_answer` 会在重试后失败时把所有选项改为 `kind=generic, claims=[]`。随后 `entailment_checks` 只从 claims 中组装该选项的已验证引用，因此回退选项的后续 entailment 检查没有引用来源；此前检索到的正文和 witness 不会自动恢复为可用个人证据。

17 题回退后全部得 0 分：12 题空答、5 题选错。回退不必然造成空答，但本次与 12/14 个空答同现，是必须优先修复的工程链路。

另用当前代码离线重放纯函数：26/26 个 `eligible_choices` 输出与日志完全一致；17 个回退案例的 `entailment_checks` 均产生四个来源和邻接上下文为空的检查。没有重新调用模型，因此这验证的是确定性处理链，不是模型修复后的效果。

现有日志只记录 `ValueError`／`ValidationError` 类型及 prompt hash，没有原始无效响应、字段路径、错误消息或截断标志。因此不能进一步断言全部是 JSON 语法错误、模型长度不足、某个特定字段缺失或 provider 兼容问题。代码还会把部分语义结构错误主动转成 ValueError。需要补足诊断再决定修复方式。

前置 witness 也不稳定：10 次 ok、9 次 partial、7 次 fallback；partial 中共 24 条引用因 `quote_not_in_source` 被拒。引用验证拒绝伪造或改写引文是正确边界；问题在于生成稳定性及失败后的恢复策略，不能靠取消验证解决。

**约束范围过宽：遗忘事实变成禁止相关建议**

Q8/D 和 Q19/B 都被同一条约束阻止：`Please forget that I take photos during family trips.`

- Q8：Gold 基于 Facebook 保持亲友联系，persona 中 `Facebook for family updates` 已在 `s0`；其中“分享旅行或活动照片”的新建议触发 blocked D。
- Q19：Gold 是摆放书、植物、家庭照片和纪念品的通用装饰建议，已通过 generic 校验，却因这条“旅行拍照”约束被 blocked B。

从忘记个人事实扩展到禁止所有照片相关建议，不符合精确作用域。当前 `13_choice_constraints.txt` 明确把约束扩展为“不能推荐被遗忘活动”，而 `constraint_pairs` 又使用词项重叠提出匹配；这为模型过度扩大范围提供了条件。Q9 成功说明规则能发挥作用，但应分清“不使用被遗忘的个人事实”和“用户明确禁止推荐某活动”。Q8 同时还有 support 回退，修复约束并不保证该题立即答对。

**建议修复顺序与验证方式**

1. **先解决 support 的 17/26 整题失败。** 记录结构化错误路径、失败环节、finish reason 和有限的失败响应诊断；区分输出格式、引用、claim 边界和字段类型。允许按选项修复、保留已通过部分，避免一个选项出错清空整题。以固定 evidence packet 重放，观察抽取成功率和空答率，而不是先扩大召回。
2. **修正建议／事实边界和准入方式。** 通用、条件建议不需要历史证明；核心前提已证实的选项应与任务相关性一起比较，避免一条无关但容易证明的人设挤掉更相关选项。使用 Q1/Q2/Q7/Q11/Q12/Q16 做回归，同时保留第三人、假设、否定和未知所有权的拒绝边界。
3. **收窄遗忘约束。** 用 Q8/Q19 验证不把旅行拍照泛化成任何照片建议；用 Q9 验证仍禁止借被遗忘偏好进行个性化。
4. **再处理上游来源质量。** Q14 检验强自述能否通过 fine；Q21 检验单条预算是否优先保留用户原句，而非助手长解释。把包内 `content_omitted` 汇总到统一监控，区分整项、整单元、来源正文和真正重复。
5. **固定题集、版本和模型做分层消融。** 答案改动先复用同一 packet，检索改动再单独重跑；同时报告错误出口、Gold 准入、可见原句覆盖与总分。对强断言依据不足的题目保留独立人工审查标签，不通过写入 Gold 或放宽所有引用检查来追分。

这些是下一轮实验的修复优先级，不是已验证的提分承诺。当前日志足以证明末端失败结构及上述具体流转，但缺少无效模型原始输出，无法还原 17 次 support 失败的全部细粒度根因。
