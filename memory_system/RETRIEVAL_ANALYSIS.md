# 召回品質與噪聲分析

更新：2026-09-18。實作策略：`single_pass_v3`；回答策略維持 `direct_evidence_v2`。

## 發現與修改

| 階段 | 原先問題 | 現在的處理 |
|---|---|---|
| 查詢規劃 | 有限畫像摘要主要受類型及新舊順序影響 | 先排除過期畫像，再優先選取與問題／選項有關的畫像；提示詞限制無關擴展 |
| 全文召回 | 英文問句中的常見詞也參與 OR 匹配 | 原文、AMU 與來源節錄共用停用詞與詞項提取 |
| 中文召回 | AMU 先 LIMIT 再排序；原文命中同分按隨機 ID 排序 | 中文相鄰雙字詞按命中數先排序，再取前 k；不跨標點拼接，保留混合語言詞項 |
| 多查詢合併 | 不同查詢的原始 BM25／相似度分數直接競爭 | 按最佳名次合併，每個查詢的第一名先於其他查詢的第二名競爭 |
| 原文來源連結 | 一個 AMU 的大量來源列可占滿預取上限 | 對不同 AMU 數量設限，避免來源重複造成召回不足 |
| 融合 | 圖與場景由直接命中擴展，卻再獲同等權重 | 降低衍生路徑權重；同一路徑相同 ID 僅投一票；零詞面關聯偏好不再額外加權 |
| 重排候選池 | RRF 前段可能全部被常見主題占據 | 最多四分之一位置保留給各直接查詢的首要命中及適用的橋接證據 |
| 候選元資料 | 向量輕量列缺少爭議狀態，導致衝突漏報 | 去重與重排前補齊權威 AMU 元資料；保留爭議及推斷提示；不同認知狀態的偏好不合併 |
| 證據選擇 | 低分、零分與未評分尾部仍可填滿證據包 | 加入保守相關性門檻及有界回退；使用者指令與遺忘規則受保護 |
| 裝包 | 重複 episode 即使沒有新增來源仍占用位置 | 只排除已完全覆蓋的來源片段，保留額外語境與較寬文件範圍 |

## 選擇策略

1. 正常重排後，若普通證據最高分至少 0.5，排除低於 0.15 的普通候選。
2. 若整批最高分不足 0.5，最多保留 8 條正分弱候選，不用單一硬門檻清空弱證據。
3. 有效評分中的零分、未評分尾部不填充證據包。重排失敗時保留最多 8 條 RRF 候選。
4. 使用者指令及遺忘規則不因主題低分被淘汰；普通指令仍占用 `top_k`。
   遺忘規則優先裝包、不占普通證據條數，但所有內容共用字節預算。
5. 不增加第二輪檢索或充分性模型。Search 使用一次規劃呼叫，再按候選數及輸入大小分批重排。

設定入口：`AML_EVIDENCE_MIN_RELEVANCE`、`AML_EVIDENCE_FALLBACK_ITEMS`。
這些預設值是保守的初始策略，尚未在完整資料集上校準。

圖路徑一般權重 0.5，多跳問題 0.85；場景一般權重 0.5，多跳、敘事及文件問題 0.85。
其他路徑維持 1.0。降權只影響候選排序，不直接刪掉橋接節點。
冷場景及其冷 AMU 可參與同輪場景召回，仍受有效版本、來源與敏感權限限制。

## 後續評測應區分的損失

以人工或資料集提供的來源標註為基準，分別檢查：

1. 有效來源是否存在，是否仍有可檢索的 AMU 關聯。
2. 必要來源是否進入任一召回路徑。
3. 對應候選是否進入重排池。
4. 是否被降噪選擇排除，或因 `top_k`／字節预算／來源重複而省略。
5. 已入包的來源是否被回答模型正確使用。

`selection` trace 及回應中的 `selection_omitted` 記錄第 4 步的選擇原因，
不將這些候選混記成 top_k 損失。`rerank_reserved_ids` 記錄第 3 步的保留位置。

目前的限制：重排誤判仍可能影響入包；弱證據超過回退上限時會被截斷；中文雙字詞
不是完整斷詞。完整 LoCoMo／PersonaMem 真實模型 Recall、MRR、精確率及答題分數
尚未重跑，不能由以上局部檢查推定整體提升幅度。

## 重排連線失敗與修正

09:25–09:30 的 PersonaMem 評測 trace 顯示，既有程序仍使用 `single_pass_v2`。
失敗題目的重排池為 80 條；依記錄的預覽及目前模板重建，單次提示詞約 6.2 萬字元，
並沿用結構化抽取的 8,192 輸出 token 上限。日誌顯示第一個請求約 120 秒失敗，
立即重試又等待約 31 秒後失敗。這能定位重排請求的大小及等待問題，
但不能僅由 `Connection error` 確定上游服務或網路的具體故障原因。

修正保留同樣的候選池容量，將單輪重排拆為有界批次：

- 每批最多 24 條候選、完整提示詞最多 24,000 UTF-8 bytes，最多 2 批並行。
- 輸出額度隨評分數量設定，24 條最多 256 tokens；原始來源引用不因分批截斷。
- 每次呼叫最多 30 秒，整輪預設最多 45 秒，並受 Search 剩餘時間限制。
- 一般連線錯誤不再立即重試；任一批失敗或逾時時取消其餘批次，整體回退有界 RRF。
- 開始前檢查剩餘呼叫額度能否覆蓋整個候選池；不混用部分批次分數。
- 回應以 `coverage_manifest.rerank_status=fallback` 標記降級，評測另記
  `diagnostics.search_degraded=true`，便於區分模型答錯與檢索降級。
