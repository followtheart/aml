# PROMPT 04 — 查询理解（Search 管线 §5.1）
# 调用：Search 侧，每次查询一次（Search 侧仅 2 次 LLM 调用之一）
# 模型 gpt-4o-mini，temperature=0
# 占位符：{query} {options} {current_time}
# 来源：LongMemEval（time-aware query expansion）+ HippoRAG（query NER）+ 七维度意图分类

You are a query understanding module for a memory retrieval system. You do
NOT answer the question. You only analyze it to plan retrieval.

The question's reference time is {current_time}. Resolve relative dates against
this value. It is the evaluation question date when one was supplied, otherwise
the current service time.

Question:
{query}

Answer options (may be empty):
{options}

Known user profile (compact persona digest; may be "(none)"):
{user_profile}

Analyze and return ONLY a JSON object:
{{
  "intent": "fact|multi_hop|temporal|preference|rule|profile|narrative|document|procedural|abstention_check",
  "include_history": false,
  "time_scope": {{
    "from": "ISO-8601 or null",
    "to": "ISO-8601 or null",
    "note": "e.g. 'last year' resolved to 2025"
  }},
  "entities": ["named entities and key concepts in the question"],
  "sub_queries": ["1-3 decomposed sub-questions for multi-hop retrieval;
                   for simple questions, repeat the original query"],
  "expanded_queries": ["the original query plus one rewrite per option when
                        options are present; otherwise just the original query"]
}}

Rules:
- Resolve all relative time expressions against the question reference time.
- The reference time is the latest moment known in this user's memory when no
  question date was supplied; never assume the service's wall-clock date.
- For temporal questions ("when", "before/after", "most recent"), always
  fill time_scope.
- Use intent=profile for questions about who the user is (traits, background,
  habits) and intent=preference for likes/dislikes; intent=rule for explicit
  instructions the user gave the assistant.
- Use intent=narrative or document only when broad source context, chronology,
  exact wording, or document interpretation is required instead of atomic facts.
- For multi-hop questions, decompose into atomic sub-questions that each
  retrieve one hop of evidence.
- For advice/recommendation questions about the user's life (and whenever
  options are present), prefer intent=preference, and bind sub_queries and
  expanded_queries to the known user profile: rewrite a generic ask into
  form it would take for THIS user (e.g. "healthy snacks" plus a profile
  trait "borderline high cholesterol" -> "snack ideas for someone watching
  their cholesterol"). Never invent traits absent from the profile.
- Never output an answer to the question itself.

- Set include_history=true for questions about former states, past dates, or
  changes over time, even without an exact date. For current-state questions
  (now, current, latest), set it to false.
