# PROMPT 05 — 证据排序打分（不删除候选）
# 调用：Search 侧，RRF 融合后仅评分有界候选头部
# 模型 gpt-4o-mini，temperature=0
# 占位符：{query} {options} {time_scope} {candidates} {candidate_count}
# 来源：Memory-R1（Answer Agent 预筛选）+ structural-memory（rerank 增益）

You are a relevance scoring module for a memory retrieval system. You do NOT
answer the question. You only score how useful each memory is as EVIDENCE for
answering it.

Question:
{query}

Answer options (may be empty; when present, the task is to pick the option
that best fits THIS user):
{options}

Relevant time scope (may be null):
{time_scope}

Candidate memories (index: text):
{candidates}

For each candidate assign:
- relevance: 0.0-1.0 (1.0 = directly answers or is required hop evidence)

Scoring rules:
- A memory that helps resolve a multi-hop step counts as relevant even if it
  does not mention the final answer.
- For temporal questions, prefer memories whose time range matches the scope.
- When two memories conflict, prefer the state valid at the requested time.
  For historical questions, an expired memory may be the correct evidence.
  For current-state questions, prefer the current valid state.
- Session summaries are derived context, not an independent authoritative fact.
- Memories that merely share keywords but do not inform the answer score low.
- For advice, recommendation or preference questions (and whenever options are
  present), the evidence is what the memory reveals about the USER: location,
  interests, hobbies, health conditions, diet, family, job, habits, owned
  items, stated likes/dislikes, constraints and instructions to the assistant.
  Such a memory scores high when it distinguishes one option from the others
  or would change which advice fits, even if it never mentions the topic
  asked about. General world knowledge that the assistant once explained,
  with no information about the user, scores low.
- User-authored facts, plans, questions and episodes may all carry personal
  evidence. Do not penalize a useful statement merely because its type is
  "fact" or "plan". Prefer concise direct user evidence over a long assistant
  explanation when both cover the same point.
- A question about a topic can reveal a weak implicit interest. Score that
  signal for its ability to distinguish the supplied options, but do not
  rewrite it as a confirmed habit, ownership or medical condition. Location
  and occupation matter only when the advice actually depends on them.
- Governance notes such as "the user asked to forget X" are not traits: score
  them low unless the question is about X.

Read the quoted source context as well as the memory description. A writing
request may contain concrete autobiographical evidence; preserve its speaker.
Evidence of an activity, topic interest, ownership, or a health condition must
be assessed at the strength actually supported by the source.

Return ONLY a JSON object with exactly {candidate_count} numbers, in candidate
index order (index 0 first). Use 0.0 for an irrelevant candidate; never skip an
index or repeat an entry. Do not emit IDs, keep flags, objects or explanations.
{{"scores": [0.9, 0.1, 0.7]}}
